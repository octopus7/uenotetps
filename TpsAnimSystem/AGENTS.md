# AGENTS 지침 (리포지토리 전역 적용)

이 파일의 지침은 리포지토리 루트부터 하위 모든 디렉터리에 전역 적용됩니다.

## 빌드/실행 정책
- 빌드는 사용자(당신)가 수행합니다. 에이전트는 직접 빌드나 실행을 시도하지 않습니다.
- 현재 CLI는 리눅스 환경에서 실행되지만, 마운트된 윈도우 볼륨을 바라보는 구조입니다.
- 이 프로젝트 결과물(실행/동작)은 윈도우 런타임에 의존하므로, 윈도우가 아닌 환경에서의 실행 시도는 무의미합니다. 따라서 윈도우 전용 실행/검증은 시도하지 않습니다.

## 금지/지양하는 동작 예시
- `build`, `run`, `test` 등 실제 바이너리 실행을 수반하는 명령 실행 시도
- 윈도우 런타임이 필요한 도구/스크립트의 직접 실행 시도
- 환경 의존 검증(예: 그래픽/사운드/드라이버 종속) 수행 시도

## 권장 작업 방식
- 정적 분석, 코드 패치, 설정/스크립트 수정, 문서화 중심으로 작업합니다.
- 검증이 필요한 경우, 로컬(윈도우)에서 사용자가 실행할 수 있도록 명령어/절차를 안내합니다.
- 변경은 최소범위·국소적(surgical)으로 수행하고, 기존 스타일을 유지합니다.

## 기타
- 네트워크/권한이 필요한 명령은 기본적으로 사용하지 않습니다. 필요한 경우에도 실제 실행 대신 방법만 제시합니다.
- 이 지침을 위반하는 자동 실행/빌드는 요청이 있어도 시도하지 않습니다(사용자가 직접 실행).

## 요청 기록(“구현요청” 트리거)
- 트리거: 사용자가 "구현요청"이라고 명시하면 하나의 태스크로 취급합니다.
- 새 태스크 시 문서화:
  - 루트 `Requests/` 디렉터리에 마크다운 파일을 생성합니다(없으면 생성).
  - 파일명 형식: `NNN_short-description.md` (예: `000_add-animation-blend.md`).
  - `NNN`: 3자리 0패딩 연속 번호입니다. 첫 요청은 `000_`, 이후 마지막 번호 + 1을 사용합니다.
  - `short-description`: 요청을 간략히 요약한 영어 설명으로, 소문자-kebab-case 권장(영문/숫자/하이픈만).
- 문서 기본 템플릿 예시:
  - `# [NNN] Short English Description`
  - `요청 요약:` 한국어로 핵심 요약 1–3줄
  - `응답:` 해당 요청에 대한 에이전트의 응답 본문(필요 시 요약 + 상세 포함)
- 종속(후속) 요청 처리:
  - 다음 "구현요청"이 오기 전까지, 기존 태스크에 종속된 후속 요청은 새 파일을 만들지 않고 같은 파일 하단에 계속 덧붙여 갱신합니다.
  - 덧붙일 때는 `## Update k - YYYY-MM-DD` 형식의 섹션을 추가하고, 각 업데이트마다 "요청 요약"과 "응답"을 함께 기록합니다.
  - 파일명은 유지합니다(번호/설명 변경 금지).
- 새 태스크 전환: 사용자가 다시 "구현요청"을 명시하면, 위 규칙으로 새 번호의 파일을 생성합니다.
- 유의: 이 요청 기록 절차는 빌드/실행을 포함하지 않으며, 필요한 경우 사용자 측(윈도우)에서 실행할 수 있는 단계만 문서로 안내합니다.

## 입력 가이드 문서화
- 입력(Enhanced Input) 관련 가이드는 다음 경로의 문서에 기록/유지합니다.
  - `Docs/enhanced-input-guide.md`
- 원칙
  - 코드로 인풋 애셋(액션/매핑 컨텍스트)을 생성하지 않습니다. 애셋은 에디터에서 생성하고 블루프린트/에셋 할당으로 연결합니다.
  - 인풋 액션의 Value Type, 매핑 컨텍스트 바인딩, 키/축 스케일, 블루프린트 연결 절차를 예시와 함께 명시합니다.
  - 인풋 스킴 변경 또는 바인딩 업데이트 시 본 문서를 반드시 갱신합니다.
  - 다른 요청 파일에서 입력 변경을 수행한 경우, 해당 변경 요약과 함께 본 문서 반영 여부를 확인합니다.
